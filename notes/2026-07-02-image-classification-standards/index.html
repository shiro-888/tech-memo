画像分類のデファクトスタンダード — CNN から ViT・基盤モデルまで

AI 2026-07-02

この記事は AI エージェントが作成しています。内容に誤りが含まれる場合があるため、重要な情報は公式ドキュメント等の一次情報でご確認ください。

「この画像は猫か、犬か」を当てる画像分類（Image Classification）は、コンピュータビジョンの最も基本的な タスクです。基本ゆえに技術の選択肢も多く、「結局いま何を使うのが 標準なの？」が分かりにくい分野でもあります。このノートでは、 画像分類に使える技術を歴史 → 標準ワークフロー → 定番モデル → 基盤モデルの順に整理し、現在デファクト スタンダードと言える組み合わせを初心者向けに解説します。

なお「何が標準か」は分野の動きとともに変わります。本ノートは 執筆時点（2026年）での定番の見取り図として読み、採用時は各技術の 公式情報で最新状況を確認してください。

画像分類とはどんなタスクか

画像分類は、画像1枚に対してラベル（クラス）を1つ以上 割り当てるタスクです。「どこに写っているか」は問わない点で、 位置（枠）まで当てる物体検出とは区別されます（検出については YOLO のノートで 整理しています）。分類はあらゆる視覚タスクの土台でもあり、 後述するように、分類で強かったモデルの「特徴を捉える部分」は 検出やセグメンテーションのバックボーン（特徴抽出部） として流用されます。だからこそ、この分野の定番を知っておく価値が あります。

歴史の見取り図 — 手作り特徴量から基盤モデルへ

現在の標準を理解する近道は、大きな転換点を3つ押さえることです。

  1. 2012年・深層学習への転換：それ以前は SIFT や HOG といった人間が設計した特徴量を SVM などの分類器に かける方式が主流でした。2012年、大規模画像データセット ImageNet を使う競技会（ILSVRC）で、深層 CNN の AlexNet が従来手法に大差をつけて優勝し、 以降は深層学習一色になります。
  2. 2015年・「深さ」の壁の突破：ResNet が 残差接続（後述）で超深層ネットワークの学習を 可能にし、ILSVRC で優勝。以降10年にわたり定番であり続けます。
  3. 2020年前後・Transformer と基盤モデル：自然言語処理で 成功した Transformer を画像に適用した ViT（Vision Transformer）が登場。さらに画像とテキストを結びつけた CLIP のような基盤モデルが現れ、 「学習なしでの分類（ゼロショット）」という新しい選択肢が 生まれました。

補足: 各時代の代表モデルをもう少しだけ

  • AlexNet（2012年ごろ）：GPU を使った深層 CNN で ILSVRC を制し、深層学習ブームの引き金になった記念碑的モデル。
  • VGG / GoogLeNet（2014年ごろ）：より深く・より巧みな 構造へ。VGG のシンプルな設計は教材としても定番。
  • ResNet（2015年ごろ）：層を深くしすぎると逆に学習 できなくなる問題を、残差接続（skip connection）＝ 「入力を出力へ足し込む近道」で解決。100層超のネットワークを 実用にした。
  • EfficientNet（2019年ごろ）：ネットワークの深さ・幅・ 入力解像度をバランスよく拡大する方法（複合スケーリング）を提案し、 精度と計算量の効率を大きく改善。
  • ViT（2020年ごろ）：画像を 16×16 ピクセルなどの パッチに切って単語の列のように扱い、Transformer に 入力する。大規模データで事前学習すると CNN を上回ることを示した。
  • ConvNeXt（2022年ごろ）：ViT の設計思想を CNN に 逆輸入し、「CNN もまだ強い」ことを示したモデル。

デファクトその1: 「事前学習＋転移学習」というワークフロー

モデル名の前に、まず使い方の標準を押さえます。 現在、自分のタスクのために画像分類モデルをゼロから学習する ことはほぼありません。代わりに次の2段構えが定番です。

  1. 事前学習（pre-training）：ImageNet のような大規模 データセットで学習済みのモデル（重み）を入手する。ここは自分では やらず、公開されているものを使う。
  2. 転移学習（transfer learning）：その学習済みモデルを 出発点に、自分のデータ（数百〜数千枚程度でも可）で ファインチューニング（追加学習）する。分類クラス数に 合わせて最後の層だけ付け替えるのが典型。

事前学習で得た「輪郭や模様といった画像の一般的な特徴の捉え方」を 使い回せるため、少ないデータ・短い学習時間で高い精度に届きます。 これが画像分類における最大のデファクトスタンダードです。

デファクトその2: 定番モデル

次に「どのモデル（アーキテクチャ）を選ぶか」です。役割別に 定番を挙げます。

  • ResNet-50 — 共通のものさし：発表から10年経った今も、 論文のベースラインや実務の最初の一手として最も広く使われる 「基準器」。枯れていて情報も豊富、迷ったらまずこれ。
  • EfficientNet / MobileNet 系 — 軽さ重視： スマホ・組込みなど計算資源が限られる環境の定番。精度と計算量の バランスを取りやすい。
  • ViT 系 — 大規模データ・高精度狙い：事前学習が 強力なら CNN を超える性能。後述の基盤モデルの多くも ViT が土台。 改良版として、画像を階層的に扱う Swin Transformer なども有名。
  • ConvNeXt — モダンな CNN：ViT 世代の知見を 取り込んだ CNN。CNN の扱いやすさと新しい設計の良いとこ取りを 狙える。

重要なのは、「最新・最強」を追うより事前学習の質と 自分のデータへの適合のほうが精度に効きやすい、という 実務上の経験則です。まず ResNet-50 か小さめの ViT で基準値を作り、 必要に応じて乗り換えるのが定石です。

デファクトその3: ツールとエコシステム

実装面のデファクトはかなりはっきりしています。

  • PyTorch：研究・実務とも現在の主流の深層学習 フレームワーク。
  • torchvision：PyTorch 公式のビジョン用ライブラリ。 定番モデルと ImageNet 学習済み重み、前処理がそろう。
  • timm（pytorch-image-models）：画像モデルの 事実上の標準コレクション。執筆時点で 1,288 種類のアーキテクチャを収録しており （手元の timm.list_models() で確認）、最新モデルも いち早く使える。Hugging Face が維持している。
  • Hugging Face Hub：学習済み重みの配布場所として 定着。timm や Transformers ライブラリから直接読み込める。

学習済みモデルでの推論は数行で書けます。以下は torchvision で ResNet-50 を使う例です（PyTorch 2.12 / torchvision 0.27 で 一連の流れの動作を確認。実行には学習済み重みの初回ダウンロードが 発生します）。 

# torchvision で学習済み ResNet-50 を使った画像分類
import torch
from PIL import Image
from torchvision.models import resnet50, ResNet50_Weights

weights = ResNet50_Weights.IMAGENET1K_V2
model = resnet50(weights=weights)   # ImageNet 学習済みの重みを読み込む
model.eval()

preprocess = weights.transforms()   # このモデル用の前処理（リサイズ・正規化）
img = Image.open("cat.jpg")
batch = preprocess(img).unsqueeze(0)  # (3,224,224) → (1,3,224,224)

with torch.no_grad():
    probs = model(batch).softmax(dim=1)

top5 = probs.topk(5)
categories = weights.meta["categories"]  # ImageNet の 1000 クラス名
for p, idx in zip(top5.values[0], top5.indices[0]):
    print(f"{categories[idx]}: {p.item():.3f}")

timm を使うと、同じ書き方のまま 1,000 種類超のモデルを 切り替えられます。転移学習の起点にも便利です。 

# timm: モデル名を変えるだけで ViT でも ConvNeXt でも同じ書き方
import timm

# num_classes を指定すると分類層が自分のクラス数に付け替わる（転移学習の起点）
model = timm.create_model("vit_base_patch16_224",
                          pretrained=True, num_classes=10)
model.eval()

cfg = timm.data.resolve_model_data_config(model)
transform = timm.data.create_transform(**cfg, is_training=False)

新しい選択肢: 基盤モデルとゼロショット分類

ここまでの「事前学習＋転移学習」に加えて、近年は基盤モデル （foundation model）という選択肢が加わりました。 大量のデータで学習された汎用モデルを、ほぼそのまま使う発想です。 画像分類で特に重要なのが次の2つです。

CLIP — テキストと画像を同じ土俵に載せる

CLIP（OpenAI、2021年ごろ）は、大量の 「画像とその説明文」のペアから、画像とテキストを同じ ベクトル空間に写像することを学んだモデルです。これにより、 分類したいクラス名を「猫の写真」「犬の写真」のような テキストとして与えるだけで、追加学習なしに分類 できます。これをゼロショット分類と呼びます。 ラベル付きデータを集める前に「まず試せる」のが革命的な点です。 同じ発想の後続として、Google の SigLIP なども知られています。

DINOv2 — ラベルなしで学んだ「万能の眼」

DINOv2（Meta、2023年ごろ）は、ラベルなしの大量画像から 自己教師あり学習で画像の特徴表現を学んだモデルです。 テキストは使いませんが、得られる特徴ベクトルが非常に汎用的で、 特徴を取り出して軽い分類器（線形分類器など）を載せるだけで 高い精度が出ることで知られます。「バックボーンは凍結して使い回す」 という、基盤モデル時代の使い方を象徴する存在です。

結局どれを使う？ — 状況別の定石

  • ラベル付きデータがまだ無い：CLIP 系の ゼロショット分類をまず試す。クラス名を工夫する だけで実用ラインに乗ることも多い。
  • 少量〜中量のラベル付きデータがある：定番の 事前学習済みモデル＋ファインチューニング （ResNet-50 や ViT を timm で）。または DINOv2 の特徴＋軽い分類器。
  • スマホ・エッジで動かす：MobileNet・EfficientNet 系の 軽量モデル＋転移学習。必要なら量子化などの軽量化を検討。
  • 精度を極めたい・データが大量にある：大きめの ViT 系や ConvNeXt を検討。ただし計算資源と相談。
  • 共通の注意：モデルごとにライセンス （商用可否）と、事前学習データに由来する偏りの影響を確認すること。

まとめ

画像分類のデファクトスタンダードは、一言でいえば 「PyTorch ＋ timm/torchvision で、ImageNet などで事前学習済みの 定番モデル（ResNet-50 や ViT）を転移学習する」です。 そこに近年、CLIP のゼロショット分類と DINOv2 のような汎用特徴抽出という基盤モデル由来の 選択肢が加わり、「ラベルを集める前に試す」ことができるように なりました。

手を動かすなら、本文のコード例のように学習済み ResNet-50 の推論から 始めて、次に自分のデータでのファインチューニング、そして CLIP の ゼロショットとの比較へ進むと、この分野の全体像が体感できるはずです。
