DINOv2 とは — ラベルもテキストも使わずに学ぶ「万能の視覚特徴」

AI 2026-07-02

DINOv2（ディノ・ブイツー）は、Meta AI が公開した 視覚（画像）の基盤モデルです。ひとことで言うと 「ラベルもテキストも使わず、大量の画像だけから 『使い回せる視覚特徴』を学んだモデル」。画像分類・ セグメンテーション・深度推定など、さまざまなタスクの土台 （バックボーン）としてそのまま流用できるのが最大の売りです。

このノートでは、DINOv2 の仕組み・強み・弱み・ライセンス・ 使い方を初心者向けに整理します。前提となる周辺知識 （自己教師あり学習など）も補足しながら進めます。画像分類全体の 中での位置づけは 画像分類のデファクトスタンダードのノートも あわせて読むと分かりやすいはずです。なお細部は情報が更新される ことがあるため、採用時は公式リポジトリで最新の事実を確認して ください。

前提: 自己教師あり学習（SSL）とは

DINOv2 を理解する鍵は自己教師あり学習（Self-Supervised Learning, SSL）です。通常の教師あり学習は「画像＋正解ラベル （猫・犬…）」のペアを大量に必要とします。しかしラベル付けは高コスト。 SSL はラベルなしのデータそのものから学習の手がかりを 自動生成するやり方で、この「ラベル集めの壁」を回避します。

DINOv2 の場合、手がかりは「同じ画像を別々に加工した2枚は、 中身は同じはず」というシンプルな事実です。1枚の画像を 切り抜き・色変換などで2通りに加工し、「どちらも似た特徴になるように」 モデルを学習させます。正解ラベルは一切使いません。

仕組み — 自己蒸留（student と teacher）

DINOv2 の学習の中核は自己蒸留（self-distillation）と 呼ばれる方式です。student（生徒）と teacher（教師）という2つのネットワークを用意し、 生徒が教師の出力に近づくよう学習します。ポイントは、教師も生徒と 同じものから作られる（外部の正解を持たない）ことです。

  1. 1枚の画像から、加工の異なる2つのビューを作る。
  2. 一方を teacher に、もう一方を student に入力し、それぞれ特徴 （出力）を得る。
  3. student の出力が teacher の出力に近づくよう、student の重みを 更新する。
  4. teacher の重みは直接学習せず、student の重みを ゆっくり平均して更新する（EMA＝指数移動平均）。teacher が 安定した「お手本」役になる。

この仕組みは、Meta が以前公開した DINO（初代）の 考え方を受け継いだものです。「DINO」という名前自体、この 自己蒸留（self-distillation with no labels）に 由来するとされます。DINOv2 はこれを、後述の大規模で高品質な データセットと組み合わせ、特徴の質を大きく引き上げました。

学習データとモデルの品ぞろえ

DINOv2 の特徴の質を支えているのが、約1億4200万枚（142M）の 画像から成る大規模データセット（LVD-142M）です。単に集めるだけでなく、 重複除去や選別で品質を高めたキュレーションが施されて いる点が、初代 DINO からの大きな進歩とされています。

まず巨大なモデルを学習し、その知識を小さなモデルへ受け渡す 蒸留（distillation）によって、用途に応じて選べる 複数サイズが提供されています（いずれも土台は ViT＝Vision Transformer、パッチサイズ14）。

  • ViT-S/14：約 2,100 万パラメータ。軽量で試しやすい。
  • ViT-B/14：約 8,600 万パラメータ。標準的な選択。
  • ViT-L/14：約 3 億パラメータ。高精度寄り。
  • ViT-g/14：約 11 億パラメータ。最大・最高精度クラス。

「まず ViT-S か ViT-B で試し、精度が要れば大きいものへ」という 選び方が現実的です。

強み — なぜ「万能」と言われるのか

  • 凍結したまま使える汎用特徴：DINOv2 の最大の特徴は、 モデルをファインチューニング（追加学習）せず「凍結」した まま、出力する特徴ベクトルの上に軽い分類器 （線形分類器など）を載せるだけで高い精度が出ること。学習コストを 大きく減らせます。
  • タスクを選ばない：分類だけでなく、 セマンティックセグメンテーション・深度推定など、 性質の異なるタスクにも同じ特徴が流用できます。だから「万能の眼」と 表現されます。
  • 密な（ピクセルに近い）特徴が得られる：画像全体を 1つのベクトルにするだけでなく、画像内の各部分の特徴も得られるため、 位置が重要なタスク（セグメンテーション等）と相性が良い。
  • ラベル不要でスケールする：ラベル付けの制約が ないので、大量データで学習しやすい。

つまり DINOv2 は、「強力な特徴抽出器を1つ用意し、下流の タスクごとに軽いヘッドを付け替える」という、基盤モデル時代の 使い方を体現する存在です。

弱み・注意点

  • テキストは扱えない：DINOv2 は画像だけで学習して いるため、CLIP のような「テキストで指定したクラスを ゼロショット分類」ができません。分類に使うには、 少量でもラベル付きデータで軽い分類器を学習する ステップが必要です（CLIP との違いは後述）。
  • 大きいモデルは重い：ViT-L / ViT-g は高精度な反面、 計算資源とメモリを要します。エッジ用途には ViT-S / ViT-B や 軽量化の検討を。
  • 入力解像度が大きめ：パッチ14の ViT を高めの解像度で 使う設計のため、素朴に使うと計算量が増えがちです（実装既定の 入力サイズは大きめ）。
  • 特徴マップのノイズ（アーティファクト）：初期の DINOv2 では、注目度マップに不自然な高反応点が出ることが報告され、 これを緩和する改良版（後述の registers）が提供されています。
  • 用途別ライセンスの違い：後述のとおり、派生の一部は 非商用ライセンスです。使うモデルのライセンスを個別に確認する 必要があります。

補足: DINOv2 with registers

上記のアーティファクト問題に対し、Transformer に レジスタ（registers）と呼ばれる計算用の 予備トークンを数個追加する改良が提案されました （「Vision Transformers Need Registers」の考え方）。これにより 特徴マップが整い、わずかな性能向上も得られるとされます。DINOv2 では _reg 付きの重み（例: dinov2_vitb14_reg）として 提供されています。特に密な特徴を使う用途では、registers 版を選ぶと よい場合があります。

ライセンス

DINOv2 のメインのコードとモデルは Apache License 2.0で 提供されており、商用利用も可能です（利用時は ライセンス全文と条件を必ず自分で確認してください）。これは、 研究用途に制限されることの多い基盤モデルの中では扱いやすい部類です。

DINOv2 の LICENSE ファイル冒頭は「Apache License, Version 2.0」。

ただし注意点として、同じリポジトリ配下でも派生プロジェクトは ライセンスが異なることがあります。たとえば医療・顕微鏡画像 向けなどの派生（Cell-DINO、XRay-DINO 等）は非商用ライセンスと 案内されています。「どのモデル／重みを使うか」ごとに ライセンスを確認するのが安全です。

使い方

公式には PyTorch の torch.hub から重みを 読み込めます。次は公式リポジトリで案内されている読み込み方法です。 

# 公式: torch.hub から DINOv2 の学習済みモデルを読み込む
import torch

# ViT-S/14（軽量）。他に dinov2_vitb14 / vitl14 / vitg14 など
model = torch.hub.load('facebookresearch/dinov2', 'dinov2_vits14')

# registers 版（特徴マップが整う改良版）
model_reg = torch.hub.load('facebookresearch/dinov2', 'dinov2_vitb14_reg')

画像モデルの定番ライブラリ timm からも同等の アーキテクチャを扱えます。以下は「凍結した DINOv2 で 特徴を取り出し、その上に線形分類器を1枚載せる」という 典型的な使い方の例です（timm 1.0 系でモデル構築・前処理・ 特徴抽出・線形ヘッドまでの流れを実際に動作確認。学習済み重みの 取得には別途ダウンロードが発生します）。 

# timm: DINOv2 を「特徴抽出器」として使う（num_classes=0 でヘッドを外す）
import torch, timm

backbone = timm.create_model(
    "vit_base_patch14_dinov2", pretrained=True, num_classes=0)
backbone.eval()

# DINOv2 用の正しい前処理（リサイズ・正規化）を自動で用意
cfg = timm.data.resolve_model_data_config(backbone)
transform = timm.data.create_transform(**cfg, is_training=False)

# 画像 → 特徴ベクトル（ViT-B/14 なら 768 次元）
# feat = backbone(transform(img).unsqueeze(0))  # 形状: (1, 768)

# その特徴に、自分のクラス数の線形分類器を1枚載せる（これだけ学習する）
head = torch.nn.Linear(768, 10)  # 10 クラス分類の例

CLIP との使い分け

画像の基盤モデルとしてよく比較されるのが CLIP です。役割が違うので、 目的で選びます。

  • ラベルがまだ無い／テキストで柔軟に分類したい → CLIP。クラス名の文を与えるだけのゼロショット分類が できる。
  • 強い視覚特徴が欲しい／分類以外（セグメン・深度など）にも 使いたい／少量のラベルで下流タスクを作りたい → DINOv2。凍結特徴＋軽いヘッドが強力。

両者は排他ではなく、目的に応じて併用・比較するのが実務的です。

まとめ

DINOv2 は、ラベルもテキストも使わない自己蒸留による 自己教師あり学習で、凍結したまま多用途に使える 汎用視覚特徴を獲得した基盤モデルです。強みは「軽いヘッドを 載せるだけで分類・セグメン・深度など幅広く高精度」、弱みは 「テキスト非対応（ゼロショット分類は不可）」「大型モデルは重い」など。 メインのモデルは Apache 2.0 で商用利用も可能ですが、 派生はライセンスが異なるため個別確認が必要です。使い方は torch.hub や timm から数行で始められます。

まずは ViT-S / ViT-B を凍結して特徴を取り出し、手元のデータで 線形分類器を学習するところから試すと、この「万能の眼」の使い勝手を 体感できるはずです。
