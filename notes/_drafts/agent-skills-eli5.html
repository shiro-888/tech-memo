必要な時だけ専門知識を読み込む、AIエージェントのAgent Skills入門

AI 2026-08-22

実はこの記事を書く作業自体、Skillsという仕組みの上で進んでいます。技術ノートの 文体ルール、公開前のチェックリスト、コミットしてpushするまでの手順。どれも 普段の雑談には出てこない専門知識で、必要になった瞬間だけ読み込まれています。

この「必要な時だけ知識を読み込む」という発想を、AnthropicはAgent Skillsというオープンな仕組みとして整理しました。名前は大げさですが、 中身は驚くほど単純です。このノートでは専門用語を避けながら、仕組みと嬉しさを かみ砕いて説明します。

そもそも何に困っていたのか

AIエージェント（自律的にタスクをこなすAI）は基本的に何でも屋です。コードも 書けるし文章も書けるし、簡単な調べ物もできます。ただしそれは「広く浅く」の 裏返しでもあります。特定の業務の細かい手順や、独自の書式のドキュメントといった 狭くて深い知識は苦手です。

こうした専門知識を教える一番手軽な方法は、会話のたびに指示を貼り付けることです。 ただ同じ指示を何度も貼るのは面倒ですし、かといって最初から全部を指示ファイルに 詰め込んでおくと、使わない知識まで毎回の会話にのしかかり、コンテキストウィンドウ （AIが一度に読み込める情報量の上限）を無駄に圧迫します。Agent Skillsは、 この板挟みを解消するために作られました。

中身はただのフォルダ

Agent Skillの正体は、SKILL.mdというファイルを含む、ただの フォルダです。 

my-skill/
├── SKILL.md      （必須。何をするスキルかと、その手順）
├── scripts/      （任意。実行するスクリプト）
├── references/   （任意。詳しい参考資料）
└── assets/       （任意。テンプレートなど）

SKILL.md自体もシンプルです。ファイルの先頭にname（名前）とdescription （このスキルが何をするものかの説明）を書き、その下に本文として具体的な手順を 書くだけです。 

---
name: commit-message
description: gitの差分から適切なコミットメッセージを作る。コミットしたいときに使う
---

1. git diffで変更内容を確認する
2. 変更の意図が伝わる1行の要約を書く
3. 必要なら詳細を箇条書きで補足する

3段階で「小出し」にする仕組み

Skillsの核心は、プログレッシブディスクロージャー （段階的な開示）と呼ばれる読み込み方にあります。

1段階目の発見で常駐しているのは、各スキルの名前と説明だけです。 たとえ何十個スキルが用意されていても、そのぶんで会話が重くなることはほぼ ありません。名前と説明を合わせても、せいぜい数行だからです。

2段階目の起動は、今の会話の内容とスキルの説明が噛み合った タイミングで起こります。SKILL.md本文がまるごと会話に読み込まれ、そこに書かれた 手順に沿って動き出します。

3段階目の実行では、SKILL.md本文だけでは足りない場合に、 同じフォルダに入っている参照ドキュメントやスクリプトが必要な分だけ追加で 読み込まれます。分厚いマニュアルの目次だけ持ち歩いておいて、該当ページだけを その都度開くようなイメージです。

たとえ話で言うと

新しく入った職場を思い浮かべてみてください。入社初日に全部署のマニュアルを 丸暗記させられることはありません。まずは「経費精算のやり方は総務のマニュアルを 見ればいい」ということだけ知っておいて、実際に経費精算が必要になったタイミングで そのマニュアルを開く。Agent Skillsがやっていることも、これに近い発想です。

何が嬉しいのか

一番の利点はコンテキストの節約です。使わない知識は会話に乗ってこないので、 たくさんのスキルを用意しておいても、普段の会話が重くならずに済みます。

もう一つの利点は使い回しやすさです。フォルダ1つなので、gitで管理してチームで 共有したり、プロジェクトをまたいで持ち運んだりできます。手順書を毎回コピペする 必要がありません。

そしてAgent Skillsは、Anthropicが原案を作りつつも、オープンな仕様として 公開されています。Claude Codeだけでなく、Cursor、GitHub Copilot、VS Code、 ChatGPT（Codex）など、対応をうたうツールはすでに数十に及びます。特定のツール 専用の機能ではなく、複数のAIエージェントで使い回せる書式になりつつある、という 点は覚えておく価値があります。

似た仕組みとの違い

紛らわしいので、2つのものと比較しておきます。

まずCLAUDE.mdのような常駐の指示ファイルとの違いです。CLAUDE.mdに書いた内容は、 会話が始まった瞬間から常に読み込まれています。頻繁に使う短いルールには向きますが、 長くなるほど毎回のコストが上がります。Skillsは反対に使う時だけ読み込まれるので、 長い手順書を置いておいても普段のコストはほぼゼロのままです。

もう一つはMCPやツールとの違いです。MCP（Model Context Protocol）やツールは、 AIが外部のサービスやシステムに実際に働きかけるための「手」にあたります。対して Skillsは、その手をどう動かすかという「手順書」に近い存在です。実際、SKILL.md の中で「このツールをこの順番で使う」と指示することもよくあります。両者は対立する ものではなく、組み合わせて使うものだと考えるとしっくりきます。

覚えておくといいこと

Agent Skillsを一言で言うと、よく使う手順や専門知識をフォルダに詰めて、必要な時 だけ開く仕組みです。難しい概念に見えて、実際にやっていることは新人研修の マニュアルとそう変わりません。もし同じ指示を何度も会話に貼り付けている作業が あれば、それは立派なSkill候補です。
